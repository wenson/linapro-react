## 结论

整改分为四个连续批次：先恢复登录落点、接口文档和图表，再修复工作台框架与移动端，然后逐页治理表格和双语，最后关闭加载反馈与测试会话污染问题。所有用户可观察变化都必须有自动化测试和浏览器截图，且不得通过增加逐行请求、恢复 Vue 页面或修改`lina-core`核心契约来解决。

## 设计边界

### 宿主和插件职责

- 工作台路由、顶部标签、顶栏、侧栏、宿主页面、认证页和全局样式在`apps/lina-web`内修复。
- 通知公告、AI 档位及其他源码插件页面在各自`frontend/`内修复；插件不得导入宿主私有`#/*`路径。
- 移动端卡片直接使用列表接口已经返回的数据，不为每一行补发详情请求。
- 不创建只转发 Semi Design 参数的通用表格包装层。每个页面保留自己的列、卡片字段和操作语义。

### 保护门禁

当前仓库根目录不存在`.contributing`。生产前端和设计文档可以继续规划，但在实际修改根`hack/`测试资产或`apps/lina-core/`前，必须先由仓库 owner 建立明确授权；本设计不把缺少授权的路径当作已经可写。

### 不采用的方案

- 不把`/admin`硬编码成某一个固定业务页，因为不同部署的菜单和权限可能不同。
- 不通过放大表格最小宽度解决移动端问题，因为这只能增加横向滚动，不能恢复核心查看和操作路径。
- 不修改后端 DTO 来适配列宽、筛选区或图表文案。
- 不缩短生产会话超时来清理自动化测试数据，避免改变真实用户会话语义。

## 修复方案

### 1. 登录落点和异常页面

新增一个纯前端的落点解析函数，输入用户`homePath`和当前可访问菜单树，输出第一个可以安全进入的页面：

1. 用户`homePath`能够匹配当前菜单页时优先使用。
2. `homePath`无效时，选择第一个可见、非外链、具有实际页面的叶子菜单。
3. 没有任何可访问业务页时进入个人资料页；个人资料也不可用时显示明确的“没有可访问页面”状态，不显示 404。

工作台只在当前路径为根路径时执行该跳转，用户主动输入不存在的路径仍显示 404。落点解析必须使用当前后端已按权限过滤后的菜单，不新增权限判断或接口调用。

### 2. 接口文档静态资源

扩展 Vite 基础路径静态文件类型表，至少正确覆盖：

| 扩展名 | 返回类型 |
| --- | --- |
| `.html` | `text/html; charset=utf-8` |
| `.css` | `text/css; charset=utf-8` |
| `.js` | `text/javascript; charset=utf-8` |
| `.json` | `application/json; charset=utf-8` |

未知文件继续按二进制文件返回，路径逃逸检查保持不变。验证必须同时覆盖根路径和非根`basePath`，并确认接口文档 iframe 能读取正文而不是只检查 HTTP 200。

### 3. 分析页图表和双语

- 在 ECharts 注册表中加入`BarChart`，并在单元测试中断言注册内容包含柱状图能力。
- 周、月、渠道和业务类型改为运行时翻译键，`useMemo`依赖当前翻译函数，切换语言后立即刷新。
- 图表网格启用标签空间计算，移动端减少横轴标签密度或旋转标签，避免星期和月份被裁切。
- 饼图不再在狭小扇区旁显示被截断的文字；完整名称放到可滚动图例和鼠标提示中。
- 深色主题继续复用现有主题模式，不复制第二套图表颜色。

### 4. 顶部页面标签

- 标签项使用`flex: 0 0 auto`，文字保持单行，超过最大宽度后显示省略号。
- 标签栏保持横向滚动，激活页面后自动把对应标签滚入可见区域。
- 手机端缩小标签最大宽度，但不允许逐字换行或把标签栏撑高。
- 关闭按钮的无障碍名称进入双语资源，不能继续拼接固定英文。

### 5. 手机顶栏和侧栏

手机顶栏只保留导航、当前租户、消息、偏好设置和用户头像。独立的语言、浅色和深色按钮在手机端隐藏，因为相同功能已经存在于偏好设置；用户名只保留头像入口，多租户选择器使用可收缩宽度。

插件顶栏插槽必须设置宽度边界，消息入口不得被裁掉。`390px`视口下顶栏`scrollWidth`不得大于`clientWidth`。

桌面侧栏固定在视口高度内，菜单区域独立滚动，品牌区域保持可见。允许多个分组同时展开，但展开数量不再改变主页面高度。

### 6. 表单抽屉和对话框

用户新增、编辑抽屉的首选宽度仍为`600px`，实际宽度不得超过当前视口。手机端表单字段、标题和底部操作必须完整可见，关闭后焦点回到触发按钮。

实施时同步扫描所有固定宽度的`SideSheet`和`Modal`。超过手机视口的页面全部采用“首选宽度加视口上限”的规则；插件页面在自身样式范围内处理，不能覆盖全局`.semi-*`选择器。

### 7. 表格与移动端信息卡

桌面表格先修正列宽总和、文字省略和横向滚动范围。只有在`1366px`常用桌面宽度下不会遮挡数据时才保留固定操作列；宽表取消固定操作列，避免其覆盖末尾数据。

手机端不显示压缩后的完整桌面表格，而是显示同一批数据的紧凑信息卡。信息卡直接复用列表结果和现有操作函数，不增加请求。核心字段如下：

| 页面组 | 手机端核心字段 | 操作方式 |
| --- | --- | --- |
| 用户、角色、菜单 | 名称、账号或标识、状态、所属范围 | 卡片底部主操作加“更多”菜单 |
| 租户、部门、岗位 | 名称、编码、状态、上级或负责人 | 卡片底部操作 |
| 字典、参数、文件 | 名称、类型或键、状态、更新时间 | 详情优先，危险操作二次确认 |
| 通知公告 | 标题、类型、状态、创建时间 | 预览为主操作 |
| 在线用户、操作日志、登录日志 | 用户、状态、时间、来源摘要 | 详情或强退入口 |
| 定时任务、任务分组、执行日志 | 名称、状态、处理器、最近时间 | 运行、详情或编辑入口 |
| AI 渠道、模型、档位、调用日志 | 名称、协议、状态、耗时或时间 | 管理、测试或详情入口 |
| 插件管理 | 名称、版本、状态、分发方式 | 详情或治理入口 |

菜单树在手机端保留层级缩进和展开收起，不把图标标识逐字换行。日志和调用记录的完整字段放入详情抽屉，列表卡片只显示判断状态所需信息。

### 8. 通知公告筛选区

插件样式只给表单字段设置最小宽度，不再给按钮设置`180px`。搜索和重置放进独立操作容器；桌面端跟随最后一个筛选字段，手机端在同一行显示并允许自然换行。

### 9. AI 档位文案

档位描述属于框架预置数据，不是管理员可编辑文本。页面按`capabilityType`、`capabilityMethod`和`code`读取插件自己的双语资源，找不到键时才回退接口原文。现有三个通用描述键扩展为能够区分能力类型和方法的键，避免把文本生成说明错误显示到图片、音频或视频档位。

能力标签前的装饰圆点删除，最近测试状态改为双语标签；协议名和模型名等产品固有名称保持原文。

### 10. 认证页面

登录、注册、找回密码和重置密码共用品牌、语言入口、卡片宽度、间距和返回登录入口。注册页按内容自然增长；找回密码和重置密码不再继承`30rem`最小高度。

登录页中的注册和找回密码入口改用 React Router 的`Link`，保证非根`basePath`下仍进入同一工作台。`390px`视口下不得出现横向滚动。

### 11. 文件预览开关

在开关旁直接显示“预览图片和 PDF”的双语标签，并使用`aria-labelledby`关联文字和控件。鼠标提示可以保留，但不再作为唯一说明；开关状态变化不增加接口请求。

### 12. 个人资料加载反馈

资料页加载时显示与最终页面结构一致的骨架，包括头像、基本字段和设置区；等待超过短暂阈值后显示“正在加载个人资料”。失败状态增加重试按钮。

实施阶段记录页面导航、资料请求开始、响应和完成渲染时间。当前接口只执行一次`GET /user/profile`，不得通过轮询或逐字段请求改善观感；若本地稳定复测仍显示接口耗时超过 1 秒，再单独形成后端性能反馈，不在本次 UI 任务中猜测修改后端。

### 13. 在线会话测试数据

保留生产会话超时、集群协调和数据权限逻辑。修复测试登录态生命周期：全套 E2E 结束后使用保存的登录态调用退出接口，再关闭上下文；中途创建的临时登录态也在对应测试清理阶段退出。

验证目标是重复运行测试后在线会话数回到运行前基线，不要求把真实有效会话隐藏或合并。该修改属于测试工具，必须在`.contributing`授权后执行，并验证 Windows、Linux 和 macOS 均不依赖平台专属命令。

## 测试与验收设计

### 自动化测试

- 路由、落点选择、图表注册、双语图表选项和加载状态使用 Vitest 与 Testing Library。
- 用户可观察修复必须更新对应 E2E，覆盖问题复现条件和修复后的结果。
- 接口文档测试必须检查`Content-Type`、iframe 正文和资源加载。
- 双语测试分别断言中文和英文实际文案，不使用双语正则代替翻译正确性。
- 测试会话清理必须验证测试前后在线会话数量不会随重复运行持续增长。

### 浏览器矩阵

| 维度 | 必测值 |
| --- | --- |
| 视口 | `1440×900`、`1366×768`、`390×844` |
| 语言 | `zh-CN`、`en-US` |
| 主题 | 浅色、深色 |
| 入口 | 登录落点、直接 URL、菜单进入 |
| 状态 | 加载、空数据、有数据、错误、操作展开 |

每个阶段截图保存到`temp/<执行日期>/`，文件名前缀使用时间，检查文字截断、重叠、横向溢出、原始翻译键、错误提示和操作可见性。

### 完成门禁

- 登录后不会短暂或最终显示 404。
- 接口文档能显示正文，控制台没有静态资源类型错误。
- 所有柱状图均有实际画面，控制台没有 ECharts 未注册错误。
- `390px`下顶栏、标签、用户表单和所有核心列表操作可用。
- 审查覆盖的桌面表格没有逐字换行、固定列遮挡或不可读列。
- 中文页面没有本设计列出的硬编码英文，英文页面没有中文残留或原始翻译键。
- E2E 重复运行不会持续增加在线会话记录。
- 类型检查、单元测试、`lint`、构建、`i18n`检查和受影响 E2E 全部通过。

## 影响评估

| 规则域 | 结论 | 说明 |
| --- | --- | --- |
| 架构 | 有限影响 | 只调整工作台展示适配和插件自有前端，不改变模块边界。 |
| 插件 | 有影响 | 通知公告、AI 和部分管理插件只修改自身 React 页面、样式与语言资源。 |
| 前端 UI | 有影响 | 路由、图表、布局、表格、表单、加载和移动端行为均需调整。 |
| API | 无影响 | 不新增或修改路径、方法、DTO 或调用次数。 |
| 后端与依赖注入 | 无影响 | 在线人数通过测试退出闭环处理，不改生产服务。 |
| 数据库 | 无影响 | 不修改表、索引、种子数据或查询。 |
| 数据权限 | 无影响 | 继续使用现有列表结果和权限过滤，不扩大可见范围。 |
| 缓存一致性 | 无影响 | 不新增缓存，也不改变会话或运行时翻译缓存。 |
| i18n | 有影响 | 宿主和启用双语的源码插件同步维护`en-US`与`zh-CN`。 |
| 开发工具 | 有影响 | Vite 静态资源类型和 E2E 清理需要跨平台验证。 |
| 测试 | 有影响 | 所有用户可观察修复都需更新单元测试、E2E 和截图。 |
| 文档 | 有影响 | 本设计、冻结 Tasklist 和后续阶段执行记录组成追踪链。 |

## 风险与回退

- 落点解析错误可能造成跳转循环；纯函数测试必须覆盖无菜单、无效首页、父级重定向和只有隐藏页四种边界。
- 手机卡片和桌面表格同时维护可能出现字段漂移；两者必须从同一行数据和同一操作函数渲染，并在组件测试中覆盖。
- 插件翻译键可能缺失；必须运行`make i18n.check`并在 E2E 中检查实际中文和英文。
- 表格取消固定操作列会降低窄桌面下的操作可见性；移动端卡片提供操作，桌面端保留明确横向滚动。
- 每个批次可以按文件回退，但不得只回退测试或语言资源而保留对应行为变更。
