# UI 全页面审计修复方案

## 目标与范围

本文将`2026-07-25`的管理员工作台页面审计转化为可执行修复方案。读者是负责`apps/lina-web`及官方源码插件 UI 的开发和测试人员。完成结果是：当前管理员可达页面不再出现路由断链或空白内容，工作台导航、列表、状态反馈和空态在桌面及移动视口中保持可读，并具备可回归的自动化证据。

本方案覆盖审计截图目录`temp/20260725/ui-audit/`中的 29 个页面。动态插件未安装、无权限页面和截图无法确认的键盘/读屏行为，不作为“已通过”的依据，而作为后续验证项。

权威执行清单是[UI 审计修复 Tasklist](2026-07-25-ui-audit-remediation-tasklist.md)`v1.0`。实现阶段必须新建执行记录；在没有实现和验证证据前，Tasklist 不得勾选。

## 已确认根因与待确认项

| 问题 | 判断 | 修复决策 |
| --- | --- | --- |
| 标签页标题竖排 | 已确认。`.tab-strip`允许滚动，但`.tab-item`可收缩，`.tab-label`未限制单行。 | 让标签项不收缩、标签文本单行省略，并验证大量标签下的高度与可滚动性。 |
| `/about`为 404 | 已确认。`about/index`已登记在`hostPages`，但没有运行路由来源。 | 在宿主补充路由中显式登记隐藏路由，沿用开发中心权限，不增加未授权菜单。 |
| 接口文档为空白 | 已确认用户结果；根因待实现前复现定位。iframe 无外层状态边界，且布局仅依赖百分比高度。 | 先固化高度/可见区域，再增加加载、超时、失败与重试状态；不能把空白视为正常。 |
| 通知管理为 404 | 页面属于`linapro-content-notice`源码插件，当前审计环境的安装、启用、菜单同步和 UI 注册状态未确认。 | 先按生命周期验证。仅在插件已启用仍失败时修复注册链路；禁用时必须隐藏入口，不创建宿主页兜底。 |
| 表格挤压与状态混淆 | 截图已证实，具体列调整需以各页面真实数据和断点复核。 | 采用页面级列契约和小型复用展示单元，不覆盖 Semi 内部选择器，不创建无语义的通用表格包装层。 |

## 设计约束

- 宿主 UI 只修改`apps/lina-web`；插件 UI 保持在各自`apps/lina-plugins/<plugin-id>/`目录。不得为了工作台展示改造`lina-core`领域契约。
- 列表、日志、AI 管理页不新增逐行详情请求；如需补字段，先评估已有投影是否足够，避免前端瀑布请求和后端`N+1`查询。
- 本轮默认不修改 HTTP API、数据库、数据权限或缓存。工作台若要改为真实统计，必须另立接口与性能设计任务。
- 所有新可见文案必须维护宿主或启用 i18n 的插件语言资源。文案在渲染期求值，不能显示原始 key。
- 用户可见行为修复必须更新 E2E；每个关键节点保存截图到`temp/YYYYMMDD/`并人工审阅。

## 修复方案

### 页面可达性与接口文档

`/about`采用隐藏的宿主补充路由，避免页面已注册却无法解析。接口文档页采用“预检 + iframe 容器 + 状态边界”：预检 API 描述可获取，iframe 容器拥有确定高度；加载超时、资源失败或渲染失败时显示本地化诊断说明和重试入口。成功路径仍复用现有同源`/stoplight/apidocs.html`与`/api.json`，不改变 API 契约。

通知管理不使用宿主路由绕过插件生命周期。实施前应确认插件状态；启用后要求菜单、路由与源码插件 UI 注册表同时可用；禁用后要求入口完全隐藏。该方案符合插件按需启停边界。

### 标签栏与工作台壳层

标签栏保持单行。每个标签使用不可收缩的最小宽度，标题使用单行省略，完整标题由原生提示或无障碍名称提供；超出视口宽度时仅横向滚动。关闭按钮必须保持可键盘访问，关闭后焦点回到当前或相邻标签。

### 列表、状态与空态

按页面定义关键列、次要列和详情字段：关键列在首屏完整可读，次要长文本使用省略加 Tooltip，操作列通过“更多”菜单收敛。时间字段不允许逐字换行。用户页的部门树改为可折叠筛选条件，避免挤占主任务区域。

加载、空数据和失败是互斥状态。加载期间显示骨架或加载提示；仅在请求成功且数据为空时显示空态；失败时显示错误原因与重试。AI 渠道、模型、档位、调用日志及消息页的空态应说明原因，并在具有权限时提供唯一主操作。

### 工作台信息语义与可访问性

工作台静态“项目、待办、动态”和分析页硬编码指标不能伪装为运行数据。默认修复为明确标注“示例/开发引导”及数据范围；若产品决定接入实时指标，另行设计有界聚合 API。版本信息长字符串提供省略、完整 Tooltip 与复制入口。危险操作必须复核确认、目标对象和结果反馈。

图标操作需要可访问名称；错误状态不只用颜色表达。需在中文、英文、浅色、深色、桌面与移动视口验证焦点、文本、布局和对比度。

## 验收与影响评估

| 规则域 | 计划结论 |
| --- | --- |
| 架构 | 有影响。通知页只经既有插件生命周期接入；工作台展示不污染宿主后端契约。 |
| 插件 | 有影响。仅核验并可能修正`linapro-content-notice`和`linapro-ai-core`前端页面/生命周期展示，不越过稳定导入面。 |
| 前端 UI | 有影响。路由、壳层、表格、状态、空态、可访问性和响应式布局均在范围内。 |
| API、后端、数据库、数据权限、缓存 | 默认无影响。任何实时指标、菜单 Seed、接口文档服务端改动都必须先升级设计与 Tasklist。 |
| i18n | 有影响。新增可见提示、空态、重试和无障碍名称须维护对应资源并运行`make i18n.check`。 |
| 开发工具 | 无影响。不得修改脚本、CI、构建入口或跨平台工具。 |
| 测试 | 有影响。所有 UI 修复均需定向 E2E、截图审查和相应组件测试；插件测试保留在插件目录。 |

## 实施顺序

先完成可达性与阻断问题，再修复全站标签栏，然后统一状态反馈、列表可读性、工作台信息语义和无障碍收口。每个阶段通过后才进入下一阶段；完整任务、依赖和验收条件见 Tasklist。
