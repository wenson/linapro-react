# Design

## 安全错误响应

统一响应边界继续展示已经使用`bizerr`定义的业务错误和可识别的参数校验错误。无法归类的数据库、文件系统或第三方错误只通过项目`logger`记录完整原因，调用端返回稳定的内部错误编号、翻译键和安全文案，不把`err.Error()`直接写入响应。

该处理只收口错误展示，不改变既有 HTTP 路由、DTO、业务错误码或数据库访问路径。数据库访问次数、数据权限和缓存行为均不受影响。

## 响应式列表状态

列表页面的加载、空数据、失败和重试状态放在桌面表格与手机卡片共同的外层。共享组件只承载稳定的“列表状态”语义，不包装或转发 Semi Table 参数；桌面和手机的数据展示仍由各页面控制。

宿主共享组件只用于宿主内建页面。源码插件在自身目录复用插件已有模式或维护插件局部组件，不从插件导入宿主私有路径，也不把插件业务逻辑放入宿主。

## 页面布局

工作台只保留工作区内容层滚动，内容使用自然高度，卡片不参与强制收缩。接口文档优先使用 Stoplight Elements 自带的响应式布局；如果手机宽度下目录仍遮挡正文，再增加目录和正文切换。宽表保留必要横向滚动，同时把操作列固定在右侧并收窄次要列。

## 表单与朗读

工作台继续保留隐藏标签页，以保持筛选、页码和编辑状态；不通过卸载旧标签页规避问题。每个表单提供稳定且唯一的表单前缀，字段控件编号包含该前缀，确保标签只关联当前表单。项目自有控件的朗读文案进入运行时语言包；第三方控件优先使用公开属性或组件语言环境，不覆盖`.semi-*`内部样式。

## 异步和视觉细节

查询条件切换时隐藏旧数据，并通过请求版本或取消信号丢弃较早请求的晚到结果。标签的当前页面状态与键盘焦点使用不同视觉样式；智能中心只限制输入区域最小宽度，不把同一宽度规则应用到按钮。

## 验证

后端单元测试验证普通内部错误不会泄露底层详情，完整原因仍进入后台诊断路径。前端组件测试验证列表失败状态在桌面和手机布局中均可见；浏览器自动化覆盖`390`、`1024`和`1440`像素宽度，以及中文、英文、浅色和深色主题的关键页面。

源码插件专属浏览器测试保留在插件自己的`hack/tests/e2e/`目录。全部修复完成后执行前端类型检查、相关 Go 包测试、国际化检查、OpenSpec 严格校验和`lina-review`。

## 影响判断

- `i18n`：有影响，宿主和已启用多语言的插件分别维护自己的运行时语言资源。
- 缓存一致性：无影响，不新增或修改缓存数据、失效机制或共享修订号。
- 数据权限：无影响，不新增数据读取、写入、列表投影或权限判断。
- 开发工具跨平台：无影响，不修改脚本、构建、生成或跨平台入口。
- 接口性能：无数据装配影响，不增加 HTTP 请求或数据库查询。
